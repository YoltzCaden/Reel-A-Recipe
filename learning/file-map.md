- server.js — known (2026-08-06, updated 2026-08-11) — the backend. The file `package.json`'s `main` field has been pointing at since it was created. Run with `node server.js`, and unlike every other script here it does not exit — `app.listen` holds the process open on port 3000 until Ctrl+C. Pulls Express in with `require`, creates the `app` object, then `app.use(express.static(__dirname))` — this hands out `index.html`, `app.js`, `styles.css`, anything in this folder, straight from disk, and (by default) serves `index.html` automatically for the bare `/` path. That's why the old `app.get("/")` plain-text route got deleted — static serving found `index.html` first and the old route could never fire again. Now also loads `.env` via `require("dotenv").config()`, builds a `pg` `Pool` (a long-lived pool of database connections, unlike `db-test.js`'s one-off `Client`), and uses `express.json()` middleware to parse incoming POST bodies. Five routes now: `app.get("/recipes")`/`app.get("/pantry")` read real rows via `pool.query()`, `app.post("/recipes")`/`app.post("/pantry")` insert new ones using parameterized `$1` queries (never string-concatenating user input into SQL — that's how SQL injection happens), and `app.delete("/recipes/:id")` (added 2026-08-19) removes one row by its route-parameter id — currently returns a 200 even if no row matched, a known gap parked for Section 10. The old hardcoded arrays are commented out but not yet deleted. Any other unmatched path still returns `Cannot GET`. Runs on Node, so it has no `document` and never will — that's `app.js`'s world, not this one.
