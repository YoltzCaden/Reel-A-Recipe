- index.html — known (2026-08-08) — the app's single page, now served by Express (`localhost:3000`). Contains no recipes or pantry items at all: both `#recipe-list` and `#pantry-list` are empty `<ul>` elements that app.js fills from data fetched off the server. Holds two forms, `#recipe-form` and `#pantry-form`, each with a text box and a submit button. The Pantry `<h2>` carries `id="pantry-heading"` so JavaScript can address that one heading instead of the first h2 it finds. Everything between `<body>` and the `<script>` tag is wrapped in `<div class="container">`, the first class in the project. - package.json — known (2026-08-06) — the project's ID card, created by `npm init`. Written in JSON, not JavaScript: no comments allowed, and a single missing comma stops npm reading it at all. Names the project (`reel-a-recipe`, lowercased because npm names can't have capitals), and records `"main": "server.js"` — the file Node should run to start the project, which doesn't exist yet. Not `app.js` (browser code, crashes on `document`) and not `index.html` (Node reads every file as JavaScript, so HTML won't parse). The `scripts` box holds named command shortcuts and currently has one placeholder `test` that fails on purpose until Section 7. The `dependencies` field now holds the project's one direct dependency, `express` → [[npm-package-json]], [[json]], [[package-managers]], [[client-vs-server]], [[dependency-tree]]
- server.js — known (2026-08-06) — the backend. The file `package.json`'s `main` field has been pointing at since it was created. Run with `node server.js`, and unlike every other script here it does not exit — `app.listen` holds the process open on port 3000 until Ctrl+C. Pulls Express in with `require`, creates the `app` object, then `app.use(express.static(__dirname))` — this hands out `index.html`, `app.js`, `styles.css`, anything in this folder, straight from disk, and (by default) serves `index.html` automatically for the bare `/` path. That's why the old `app.get("/")` plain-text route got deleted — static serving found `index.html` first and the old route could never fire again. Holds `recipes` and `pantry` arrays (temporary duplicates of the ones in `app.js`, until Section 6's database becomes the one source of truth) and two routes, `app.get("/recipes")` and `app.get("/pantry")`, each replying with its array via `response.json()`. Any other unmatched path still returns `Cannot GET`. Runs on Node, so it has no `document` and never will — that's `app.js`'s world, not this one. Edit this file and the running server keeps serving the old code until you Ctrl+C and start it again → [[commonjs-require]], [[express]], [[express-routes]], [[express-static-serving]], [[localhost-ports]], [[callbacks]], [[long-running-processes]], [[server-restart-required]], [[client-vs-server]], [[json]]
- package-lock.json — known (2026-08-06) — the itemised receipt for `node_modules/`. Machine-written — you never edit it — but it *is* committed, so anyone who clones this repo and runs `npm install` gets byte-identical packages → [[dependency-tree]]

- app.js — known (2026-08-06) — the page's JavaScript, loaded by a <script> tag at the bottom of index.html's <body> so the page exists before it runs, now served by Express (`localhost:3000`) rather than opened directly.
